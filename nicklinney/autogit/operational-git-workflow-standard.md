## Purpose

This standard defines the minimum governed workflow for source-control operations across the ecosystem.

## Minimum Control Areas

- branch purpose and lifecycle
- merge and review expectations
- tagging and release linkage
- attribution and commit identity
- traceability between changes and governed artifacts

## Governance Rule

A Git workflow is not governed unless its branching model, attribution logic, and release relationship can be described as controlled practice rather than individual preference.

## Minimum Artifact Expectations

Each governed Git workflow should identify:

- branch classes
- merge authority
- release tagging rule
- attribution model
- rollback or reversion posture
