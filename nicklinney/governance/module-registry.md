# Module Registry

## Purpose

This page is the formal registry of recognized modules within the NickLinney.* ecosystem.

A module is a named, governed conceptual or operational domain with a distinct purpose, boundary, and relationship to the wider ecosystem.

For a more user-facing exploration experience, see the [Module Directory](/nicklinney/modules).

For the retrieved-export-backed registry recovery, see [NickLinney.Modules Canonical Module Registry](/nicklinney/modules/canonical-module-registry).

## Registry Boundary

The canonical module set explicitly excludes personal or adjacent domains such as `Network`, `Audio`, `Onyx Dragon Games`, `Homelab`, `Retail`, and `Philosophy`.

These may influence or consume the ecosystem, but they are not canonical NickLinney.* modules.

`SyntheOS` is also treated here as a planned product rather than as a canonical Project-space module.

## Registry Rules

Each module should eventually have:

- a canonical name
- a purpose statement
- a classification
- a governance status
- key relationships
- authoritative source documents

## Registered Modules

### NickLinney.System

Purpose: defines the canonical ontological information model, architectural principles, and information substrate for the ecosystem.

Classification: foundational semantic and system-architecture domain.

### System

Purpose: research and incubation project for ontology, graph structures, information theory, and experimental concepts prior to promotion into canonical modules.

Classification: research and incubation domain.

### NickLinney.Agents

Purpose: governs autonomous agents, personalities, cognitive behaviors, capabilities, lifecycle management, collaboration models, governance, and execution semantics.

Classification: autonomous systems and orchestration domain.

### NickLinney.Contracts

Purpose: defines contract-first architecture including interfaces, schemas, APIs, compatibility guarantees, and interoperability rules.

Classification: architecture and interoperability domain.

### NickLinney.DataInfrastructure

Purpose: governs enterprise information infrastructure including relational, graph, vector, document, and distributed data systems and their lifecycle management.

Classification: information substrate and data architecture domain.

### NickLinney.DevOps

Purpose: governs engineering automation, CI/CD, Infrastructure as Code, deployment strategies, build systems, testing, and release engineering.

Classification: engineering automation and delivery domain.

### NickLinney.env

Purpose: defines reproducible development environments, workstation provisioning, shell configuration, runtimes, and developer tooling.

Classification: development environment domain.

### NickLinney.KnowledgeManagement

Purpose: governs document control, provenance, versioning, historical retention, canonical-source declaration, and recovery of fragmented artifacts.

Classification: knowledge governance and document-control domain.

Primary page: [NickLinney.KnowledgeManagement](/nicklinney/knowledge-management)

### NickLinney.Modules

Purpose: governs module classification, metadata, dependency graph, lifecycle state, ownership, compatibility, and architectural relationships across the ecosystem.

Classification: architectural registry and catalog domain.

### NickLinney.Ops

Purpose: governs operational procedures, recurring execution, operator responsibilities, incident response coordination, service reliability, and runtime administration.

Classification: operational governance domain.

### NickLinney.SecOps

Purpose: governs operational cybersecurity including continuous monitoring, detection engineering, incident response, vulnerability management, and defensive automation.

Classification: operational security domain.

### NickLinney.Security

Purpose: defines the safety, security, assurance, and maximum-risk governance posture for the ecosystem.

Classification: constitutional governance and assurance domain.

### NickLinney.SoftwareFactory

Purpose: governs the end-to-end software production ecosystem, including planning, architecture, implementation, validation, documentation, testing, release engineering, and AI-assisted development methodologies.

Classification: automated production and lifecycle domain.

### NickLinney.Strategy

Purpose: defines executive strategy, portfolio management, organizational governance, technology roadmaps, investment prioritization, and long-term planning.

Classification: strategic governance domain.

### NickLinney.AutoGit

Purpose: governs repository lifecycle management, branching strategy, release automation, semantic versioning, repository hygiene, and source control automation.

Classification: source-control governance domain.

### NickLinney.YubiKey

Purpose: defines standards and procedures for hardware-backed identity, authentication, authorization, FIDO2, PIV, SSH, GPG, secrets management, and hardware-rooted trust.

Classification: identity, trust, and hardware-authentication domain.

## Relationship Notes

The ecosystem currently reflects a layered pattern:

- theory and incubation domains establish conceptual foundations
- platform and agent domains govern semantics, intelligence, and information substrate
- engineering domains govern production, contracts, environments, and source-control discipline
- operations and assurance domains govern runtime, security, reliability, and trust
- strategy and knowledge-management domains govern long-term direction and institutional memory
