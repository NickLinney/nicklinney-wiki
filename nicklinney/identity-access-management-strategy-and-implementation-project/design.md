## Purpose

This page anchors the design phase of the `NickLinney.IdentityAccessManagement` Strategy and Implementation Project. It provides a navigable starting point for the cabinet's design working sessions and preserves the relationship between design decisions, meeting artifacts, and future implementation planning.

## Design Goals

- define a governable IAM operating model for humans, agents, and service accounts
- establish record, approval, and evidence boundaries before selecting technologies
- compare candidate architecture patterns against enterprise capability requirements
- preserve traceability from the CVO kickoff input and executive retrospective corpus into design decisions

## Design Constraints

- IAM is a cross-module enterprise service rather than a narrow security add-on
- live secrets and runtime evidence must not be confused with publication artifacts
- design decisions must remain evidence-led and bounded to current enterprise maturity
