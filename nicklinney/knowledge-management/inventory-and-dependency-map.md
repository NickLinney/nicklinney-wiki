# Knowledge Management Inventory and Dependency Map

## Purpose

This page extracts from the enterprise inventory the modules and artifacts most relevant to the goal of populating and maintaining the wiki with full versioning and historical retention.

## Priority Modules Mentioned in the Enterprise Matrix

### Knowledge Management

Directly implicated through proposed or implied control artifacts for document-state governance.

### Enterprise Governance

Provides authority, approval relationships, publication rules, and cross-module policy legitimacy.

### NickLinney.AutoGit

Relevant to repository structure, document naming, and recovery of chat-generated artifacts into version-controlled form.

### NickLinney.DataInfrastructure

Relevant to machine-readable register fields, provenance schema, identity, and relationship modeling.

### NickLinney.Security

Relevant because evidence handling, source preservation, and assurance records require strict provenance and retention discipline.

### NickLinney.SoftwareDevelopment

Relevant because documentation is treated as a first-class architectural asset and because standards need durable lifecycle control.

### NickLinney.DevOps

Relevant because deployment, release, rollback, and operational records are part of the governed document estate.

### NickLinney.Ops

Relevant because governance records, minutes, cadences, and operating procedures require authoritative retention.

### NickLinney.Agents

Relevant because agent-produced artifacts and recovered chat outputs need origin and authority tracking.

## High-Priority Knowledge Management Artifacts Explicitly Mentioned in the Matrix

### Departmental Document Control and Publication Standard

Need: define draft, reviewed, approved, canonical, superseded, deprecated, and archived states across all modules.

### Document Naming and Ownership Standard

Need: define canonical title structure, module prefixing, identifiers, version fields, owners, approvers, and repository location.

### Enterprise Document Register Schema

Need: define machine-readable fields for title, module, type, status, authority, source location, version, relationships, and confidence.

### Chat-Generated Artifact Recovery Procedure

Need: govern extraction, consolidation, review, naming, and repository admission of documents that currently exist only in conversations.

### Canonical Source Declaration Record

Need: identify which copy of a document is authoritative when duplicates exist across chat, uploads, repos, exports, and derivatives.

## Upstream Supporting Artifacts Also Mentioned in the Matrix

These are not owned solely by Knowledge Management, but they are important dependencies for the wiki-retention goal.

- Enterprise Documentation Inventory and Expected Artifact Register
- Portfolio and Module Registry
- Repository Information Architecture Standard
- Architectural Decision Record Standard
- Executive Meeting Minutes Standard and Template
- Artifact Provenance and Lineage Standard
- Enterprise Object Identity and Relationship Standard
- Software Documentation and Repository Architecture Standard

## Historical Retention Implications

The matrix implies that the wiki must preserve not only current-state content, but also:

- origin of content
- previous authorities and superseded versions
- whether the page was recovered from chat, file, upload, or composite synthesis
- relationships between a canonical page and its supporting evidence
- distinctions between native policy, working concept, proposed artifact, and external reference

## Immediate Knowledge Management Priorities

1. Establish document states and publication rules.
2. Establish canonical naming and ownership rules.
3. Define the register schema for all tracked artifacts.
4. Recover high-value chat-generated artifacts into controlled wiki pages.
5. Declare canonical sources whenever duplicate copies exist.
6. Define historical-retention rules for superseded, deprecated, and archived pages.
