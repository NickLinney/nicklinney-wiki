# Chat-Generated Artifact Recovery Procedure

## Purpose

This procedure governs how documents that currently exist only in chat conversations, pasted bundles, or composite generated fragments are converted into controlled artifacts.

## Trigger Conditions

Use this procedure when:

- a document is known to exist substantially in chat
- a document is embedded inside a conversation transcript bundle
- a standard exists only as a section within a larger generated artifact
- a frequently referenced document lacks a durable canonical copy

## Procedure

### 1. Identify the Logical Artifact

Determine whether the content represents a distinct document identity rather than a passing discussion.

### 2. Collect Source Fragments

Gather the full available markdown, transcript excerpts, uploaded bundles, or related source materials.

### 3. Normalize Into a Candidate Draft

Assemble the content into a single controlled draft without silently changing substantive meaning.

### 4. Assign Provisional Metadata

Record:

- title
- owning module
- document class
- source origin
- confidence
- candidate canonical path

### 5. Review for Boundaries and Duplicates

Check whether the artifact duplicates another page, should be split into separate artifacts, or should remain a section of a parent document.

### 6. Publish With Non-Canonical Status if Needed

If not yet fully approved, publish as Draft or Reviewed rather than pretending it is already canonical.

### 7. Resolve Canonicality

Create or update the canonical-source declaration when duplicate copies or competing variants exist.

### 8. Link Into the Register

Ensure the recovered artifact has a register entry and relationships to parent standards, evidence, and supersession lineage.

## Recovery Principle

The goal is controlled preservation, not premature polishing. It is better to recover a high-value artifact with explicit caveats than to leave it stranded in chat history.
